## 1. 研究问题

**G0 产品价值（根本性产品门禁，三问）**——DISCUSSION_RECORD §7："Is downloading easier, more reliable, and lower-friction?"

| 编号 | 问题 | 证据形式 |
|---|---|---|
| G0-1 easier | 用 xDownload 把文件下到盘上，是否比常规方式**更省力**（净时长更短、步骤更少）？ | 各任务 A/B 净时长与步骤数对比 + 省力度 Likert |
| G0-2 more reliable | 下载失败发生后，xDownload 是否让用户**更容易发现、理解并从失败中恢复**？ | T-C 错误呈现形态、自发恢复动作、T-C1+T-C2 合计成本 |
| G0-3 lower-friction | 全程主观**摩擦**（不确定文件去哪、不知道进行到哪、怕下错）是否更低？ | 可控度 Likert + 自由备注 |

**G1 AI 增量**——"Does AI solve valuable cases deterministic methods cannot?"

本候选判定为 **NOT_APPLICABLE_THIS_CANDIDATE**，依据见 §8。G1 独立失败不否定 G0（§7 引文："Only G0 is a fundamental product-level gate"）。

## 2. 参与者与顺序设计

- 参与者：**≥2 名真实人类**；P1=owner（熟悉产品），P2=非开发参与者（对本产品接触最少）为佳。参与者只以匿名代号（P1/P2/…）出现在入仓表单中，不采集身份信息。
- 每人完成 arm A（常规基线）与 arm B（xDownload 终版候选），**三个任务在两 arm 下完全同形**。
- 顺序交替抵消学习效应：**P1: A→B；P2: B→A**。若参与者多于 2 人，按序号奇偶交替（奇数 A→B，偶数 B→A），并在表单 `task_order` 如实记录实际顺序。
- 两 arm 可同日先后执行；arm 间隔与日期如实记录，不做修饰。

## 3. 可比性控制（P12）

P12：同 host / fixture / baseline 才可比较。落地方：

1. **同主机**：两 arm 在同一台物理机、同一 OS 上完成；主机形态（OS/版本/CPU/内存简述）记入表单 `host` 字段。
2. **同网络**：同一网络环境、同一会话窗口内完成两 arm，避免跨时段网络差异。
3. **同夹具**：同一本地受控 fixture 服务器与同一批确定性字节文件（sha256 预先记录）；夹具在终版候选安装后启动，端口用动态空闲口。
4. **同基线**：arm A 工具两人完全一致（见 §5），不允许一人浏览器一人 curl。
5. 不可避免的任何环境差异（系统更新打断、杀毒软件拦截等）**如实记入表单备注**，不事后修饰、不删除会话。

## 4. 任务定义（三任务，arm 间同形）

夹具：本地受控 HTTP 服务（127.0.0.1 动态端口），提供：

- `f1.bin`：~50MB 确定性字节，**经一次 302 重定向**到真实资源路径（重定向跳转不计为失败）；
- 5 个小文件（各 ~1MB）与其清单页（manifest）；
- 一个返回真实 HTTP 404 状态码的路径（供 T-C 首次尝试）。

| 任务 | 给参与者的任务原文（照抄入表单） | 成功判据 |
|---|---|---|
| T-A 直链 | "请把这个文件下载到磁盘：`<f1 重定向 URL>`。完成后告诉我文件在哪里。" | ~50MB 文件完整落盘（大小/哈希核对一致）且参与者能指出其位置 |
| T-B 批量 | "请把这个清单里的 5 个文件都下载到磁盘：`<manifest URL / 清单>`。" | 5 个文件全部落盘且完整 |
| T-C 失败恢复 | 第一步："请下载这个文件：`<404 URL>`"（必然失败）。观察参与者自发反应；当参与者求助或明确放弃后，主试按剧本说："正确的地址其实是 `<正确 URL>`，请把它下载完成。" | 正确文件落盘；T-C1（失败尝试）与 T-C2（重做完成）分段计量 |

- T-C 计量切分：**T-C1** = 对失败 URL 的尝试、错误暴露与参与者自发诊断/恢复尝试；**T-C2** = 拿到正确 URL 后的重做完成。G0-2 的证据主要在 T-C1 的错误呈现形态与自发恢复行为，加上 T-C2 的重做成本。
- T-C 剧本是主试唯一允许的主动干预；其余任务中主试不提示、不代操作。
- 夹具 404 的失败呈现按各 arm 真实形态记录（例如浏览器可能把 404 页面当作文件"成功"保存——这是真实摩擦数据点，如实记录，不计为夹具故障）。

## 5. 两个 arm

**arm A（常规基线）**

- 浏览器默认下载流程：点击直链 → 浏览器内建下载器完成落盘；T-B 用同一浏览器对清单 5 文件逐个下载；T-C 同浏览器先点失败 URL、恢复阶段点正确 URL。
- 基线工具**两人一致且固定为浏览器默认下载**（不使用 curl/wget/第三方下载器），避免工具熟悉度混淆；参与者平时的下载习惯在表单备注中记录（供分析，不改变基线）。

**arm B（xDownload 终版候选）**

- 安装包：`xdownload-v0.2.1-windows-x64.zip`，sha256 `9ea811694a2b8638a307266a402dc25f5ec0a8eead371f4b12cb0ba564f6e718`；源修订 `52a39451dafd44ff3c2d03b93c95db78c3add126`；contentHash `87a257f5b0d1727b8ebdcf1a27b3b76b8672a1031d2855df616fbdbc098360e9`（verify.cmd PASS 148 files，哈希绑定证据见 `../platform/EVIDENCE.md` §1）。
- 真实 `install.cmd` 安装（允许参与者自行阅读 INSTALL.txt，与真实用户一致；安装全程计时记入表单 `install_duration_sec`）。
- 安装后任务表面：**Desktop UI 或 CLI 由参与者自选**，选择如实记录在表单 `arm_b_interface` 字段；不培训、不给操作脚本。
- 同一参与者的 arm B 三任务复用同一次安装。

## 6. 计量口径（两 arm 同一口径，口径冻结）

| 维度 | 定义 | 记录方式 |
|---|---|---|
| 净时长 | 起点=参与者读完任务文本、确认理解、开始动手的瞬间；终点=产物文件在目的地确认存在（或明确放弃/超时中止）。T-C 净时长=T-C1+T-C2 | 秒表或录屏时间戳，精确到秒 |
| 步骤数 | 参与者发起的原子操作：每次点击/快捷键/回车执行/URL 确认各计 1；纯等待不计 | 主试流水逐条勾记 |
| 错误与恢复 | 每次非预期状态：失败提示出现、错误内容被当作文件落盘、重试、取消重来 | 事件+时刻+恢复动作 |
| 求助 | 参与者向主试提问或求助；分环境类（夹具/网络问题）与任务类（怎么做） | 次数+内容摘要 |
| Likert 1-5 × 2 轴 | 省力度（"这件事有多省力"）与可控度（"你对下载过程的掌控感"）；每任务各评一次，每 arm 结束再总评一次 | 表单数值 + 自由备注 |

- 主试不代操作、不代答（T-C 剧本除外）；参与者对"求助"口径以协议定义为准，会前口头说明一次。

## 7. 隐私边界

- **不采集**：浏览历史、cookie、个人身份信息（姓名/联系方式/账号/头像）、屏幕上与任务无关的内容。
- **录屏（可选，须参与者同意）**：只捕获夹具页面与 arm B 本地 UI 窗口；录屏文件仅存本地，**不入仓**；入仓表单只含脱敏后的事件流水。
- 入仓前脱敏自查（模板末内置勾选项，对照本节）：无真实姓名、无含个人标识的主机名/路径、无任务外个人信息。
- 参与者可随时要求停止并要求删除已产生数据；如愿删除则在表单登记"已按参与者要求删除"，不保留残卷。

## 8. G1 判定：NOT_APPLICABLE_THIS_CANDIDATE

- 本候选（源修订 52a39451…，zip 9ea81169…）的全部用户路径均为**确定性方法**：CLI 显式命令与参数、Desktop UI 表单与按钮、扩展上下文菜单与权限面板。没有任何模型推断/AI 辅助参与用户可感知的决策。
- K 通路（recipe/knowledge 知识复用，T06/T12 证据域）是内部确定性知识机制，**不构成 AI 功能宣称**：它不面向终端用户暴露，也不以 AI 生成为产品卖点。
- 因此 G1 的实验问题（AI 是否解决确定性方法解决不了的有价值场景）在本候选上**没有可测试对象** → 判定 **NOT_APPLICABLE_THIS_CANDIDATE**，如实记录于 RESULTS（回填后保留该判定，不因 G0 结果改写）。
- 该判定不是"AI 增量为零"的实证结论，而是范畴判定（见 `LIMITATIONS.md` §8）；亦不构成跳过 G0 研究的理由——G0 三问仍须真人会话数据。
- 分层依据：DISCUSSION_RECORD §7——G1–G3 可独立失败而不否定 G0 产品。

## 9. 排除与中止条件

**会话级排除（该任务作废、修复后整任务重跑）**

- 环境故障：夹具崩溃、网络中断、系统更新/杀毒拦截等非参与者过错的中断；环境事件记入备注。
- 数据不可归因：缺起止时间戳且无录屏佐证，净时长无法复算。
- 发现代填或非真人操作：整卷作废并如实记录（这同时是流程违规事件）。

**参与者级排除**

- 深度参与 xDownload 开发/验证的人员不得充当"非开发参与者"；owner 只能以 P1（熟练用户画像）参与，其经验偏差在 `LIMITATIONS.md` §4 声明。

**中止条件**

- 参与者随时可要求停止，不问原因；数据按其意愿保留或删除。
- 单任务超过 15 分钟仍未完成：中止该任务记 `timeout`——timeout 本身是 G0 数据点，如实入表，不丢弃。
- arm B 安装失败且参与者自行排查超过 15 分钟：中止安装；安装障碍如实记录为产品发现，不归咎参与者，不计为参与者失败。
