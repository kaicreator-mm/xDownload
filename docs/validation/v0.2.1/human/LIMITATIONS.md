# xDownload v0.2.1 — T17 预定局限（与协议同版本冻结，#266）

- 定稿日期：2026-11-01
- 性质：以下局限在**数据产生之前**预定，不受结果好坏影响；`RESULTS.md`（回填后）必须原样引用本文件，不得因结果有利而弱化。

## 1. 样本量

≥2 名参与者 × 2 arm × 3 任务 = ≥12 个任务样本。只产生**方向性信号**（净时长/步骤数/错误形态的量级对比），不做统计显著性推断；中位数与极差仅为描述统计。任何"显著优于"类措辞都是越界宣称。

## 2. 任务广度

3 个任务只覆盖直链（~50MB、一次重定向）、批量（5 小文件）、失败恢复（404→正确 URL）三类场景。未覆盖：HLS 流媒体（T15 证据域）、断点续传与重启恢复、浏览器扩展路径、超大文件、真实弱网/高延迟/限速。G0 结论限定为"这三类任务上的努力度"，不是"下载这件事的全部"。

## 3. 单主机

P12（同 host/fixture/baseline 才可比较）保证内部效度，但牺牲外部效度：结论不能推广到其他 OS、浏览器、网络条件、硬件形态。平台适用面以 T16 为准（仅 win32-x64 + Node 24 实测）。

## 4. 参与者经验偏差

- P1（owner）熟悉产品设计与 CLI，arm B 天然占优；其对浏览器基线同样老练。其数据只能作为"熟练用户"画像，不冒充普通用户。
- 非开发参与者（P2）可能对命令行陌生：若 arm B 选择 CLI，CLI 学习成本计入净时长——这是真实的一次性成本，不是噪声；若选择 Desktop UI，则 CLI 表面未被人测。
- 顺序交替（A→B / B→A）只能抵消部分学习效应；2 人样本无法完全平衡任务内学习与疲劳效应。

## 5. 夹具与环境

- 本地回环 fixture 无真实网络抖动/限速：可靠性表现偏乐观，T-A 的重定向与 T-C 的失败恢复都在受控条件下发生。
- T-C 的 404 呈现依赖夹具返回真实 404 状态码；arm A 浏览器可能把 404 页面当文件"成功"保存——这是真实摩擦数据点，如实记录，不计为夹具故障。
- fixture 由主试准备：主试对夹具行为的先验知识可能间接泄露给参与者（如摆放方式），无法完全消除。

## 6. 计量粒度

- 净时长靠秒表/录屏人工起止，存在秒级误差；步骤计数的"原子操作"边界由主试按协议 §6 判断，有主观空间。
- 求助计数依赖参与者与主试对"求助"口径的一致理解（协议口径：向主试提问即计）。
- Likert 1-5 是个人主观感受，不是客观测量；两轴（省力度/可控度）可能高度相关，不应当作独立证据源。

## 7. arm B 一次性成本

安装与首启成本（阅读 INSTALL.txt、运行 install.cmd、扩展 ID 绑定）是 arm B 的真实成本。对"长期使用"场景是一次性摊销，对"单次下载"场景是全额成本。RESULTS.md 须两种口径都呈现，不隐藏安装成本；本研究的 30-45 分钟会话内无法度量长期摊销后的体验。

## 8. G1 判定

G1=**NOT_APPLICABLE_THIS_CANDIDATE**（依据 `PROTOCOL.md` §8）。这不是"AI 增量为零"的实证结论，而是"本候选无 AI 辅助用户路径可测"的范畴判定：K 通路（recipe/knowledge 复用）是内部确定性机制，不构成 AI 功能宣称。未来含 AI 用户路径的候选需要另行设计 G1 实验，本协议不预支该结论。
