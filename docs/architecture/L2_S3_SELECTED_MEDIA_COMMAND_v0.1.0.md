# S3 selected-media Core execution authority — proposed narrow successor (v0.1.0)

**Owner:** #101 S3 Core/surface implementation, after #105 / PR #107 S3 architecture successor.
**Decision state:** REVIEW_REQUIRED; **not executable authority before exact-HEAD independent L2 adoption**. Do not mutate frozen Product PRD, original L2 or Task DAG. **Reuses** the reviewed S1 Core-owned intent/journal/control pattern (#103) and existing T008 Media port; does not silently extend S1 or S2.

## 1. Single concern and explicit API/version change

For **public, self-contained direct media file only**, permit a closed **two-step S3 authority pair**: `CONFIRM_S3_CANDIDATE` (durable, no effect) followed by `EXECUTE_S3_SELECTED_MEDIA` (durable effect intent), each gated on `xdownload.core-seam@1.2.0` (major 1). Existing wire kinds, response vocabulary, immutable contract and confirmed snapshot commands are unchanged. **1.1 is S1-only**: a 1.0/1.1 envelope attempting either new command fails `UNSUPPORTED_ENVELOPE_VERSION` before intent, work item or HTTP; an older Core lacking S3 rejects the unknown command/replay rather than reinterpreting it as S1/S2. Old 1.0/1.1 commands/queries remain accepted under their existing peer gates. Reopen an S3 journal with old Core is an explicitly unsupported downgrade; fail closed without side effects. Exact minor parsing applies to the S3 opcode, not only major-1 support.

This addendum is a **proposal to review**, not evidence that the command exists. Do not implement command from this unadopted document. Implement using separate, bounded Contract → Core → Shipped User Surface → Validation PRs; each change to authority requires exact-SHA review.

## 2. Selection and admission (no new discovery authority)

1. The installed browser or CLI presents the **explicit source and one chosen media variant**, including provenance/authorization context and applicable structural requirements. Auto selection is allowed only for an independently unambiguous supported candidate. Otherwise user confirmation is explicit; model ranking is untrusted recommendation, never evidence of file validity.
2. Core first accepts a `SINGLE_RESOURCE` AcquisitionContract with `requestedScope.kind=single_resource`, continuation NONE and its original target identity. The existing `CONFIRM_SNAPSHOT` command freezes the *exact single selected member/variant* with snapshot contractId, selectedMemberIds, requested scope/authorizationContextRef, permitted source identity and selection claim. The Core must reject candidate not present in confirmed snapshot, stale revision, changed scope, member/variant mismatch, unsupported source and unconfirmed automatic selection. A snapshot's member identity is **not** proof of downloaded bytes.
3. Only the authorized installed peer surface (explicit CLI or independently authorized browser-extension/Native Messaging path) can submit S3 command, and only for the current confirmed contract and snapshot. The peer/aggregate/requestId/revision and the same-user/install boundary remain binding. A browser page, AI suggestion or Recipe cannot author Core truth or call the command directly without the existing privileged, locally authenticated transport.
4. The **metadata-only** `CONFIRM_S3_CANDIDATE` payload contains exactly `snapshotId`, `memberId`, selected `locatorUri`, nonempty bounded `declaredRedirectHosts`, optional independently published lowercase SHA256 / total bytes / expected Content-Type, and a **Core-registered supported mediaProfileId** plus optional **additional** nonempty, bounded media assertions. The Core obtains its mandatory MediaPolicy/structural validation from the pinned supported profile; the user/browser/model cannot author a weaker sufficient MediaPolicy, replace the required track/container list, or convert an unsupported profile into PASS. It binds the user-confirmed candidate to the *already confirmed* single selected snapshot member, contract, peer authorization and revision. Core verifies mediaProfileId against a versioned closed supported-profile registry (profile revision pinned in the intent) and commits an immutable secret-free candidate record binding the selected source, Core-approved profile, extra assertions, user-confirmation provenance and selected member; it derives the canonical candidate identity from `(contractId,snapshotId,memberId)`. Confirmation cannot be synthesized from an untrusted page event or AI suggestion: the installed privileged surface must attest an explicit user action (or a separately proven unambiguous AUTO rule) over that exact displayed variant and authorization context. The surface supplies **no** trusted `candidateEvidenceRef`: the Core's durable candidate record is the sole reference, and is only evidence of user selection, **not** independent bytes/Target/Media validation. The **effectful** `EXECUTE_S3_SELECTED_MEDIA` payload contains only `snapshotId`, `memberId`, `artifactId`; Core looks up exactly one approved candidate record to obtain the frozen locator/host graph and derive the pinned Core-owned MediaPolicy; extra assertions may strengthen but never weaken it. Missing/changed candidate, inconsistent snapshot, unconfirmed member, or second non-identical confirmation fails closed, never guesses a URI. Neither payload may carry raw cookie, bearer token, browser auth header, script, unrestricted URL expansion or arbitrary code. Unknown fields reject before journal; canonical effect/work/artifact lengths are checked before effects.
5. No new generic `download(url)` authority. S1 payloads never become S3 merely by attaching `mediaPolicy`; S3 never bypasses its confirmation. A changed selection or detected changed representation requires an explicitly new successor contract/snapshot and candidate confirmation, not a silent payload rewrite. `CONFIRM_S3_CANDIDATE` must never treat a selected URL/MediaPolicy as independently validated truth.

## 3. Execution, truth and hostile examples

Core reads the preceding Core-journaled immutable candidate record, journals accepted S3 execution intent and its stable selected identity **before** external effects, registers exactly one Core-owned lineage/work item and reserves transfer budget, and dispatches **only** `DirectHttpAdapter` with `slice='S3'` and declared provenance-bound public locator. The single T015 scheduler/writer and frozen T007 projector own acceptance/terminal facts. Never return COMPLETE from command ACCEPTED or HTTP 2xx.

Every required layer — Target, Transfer, Format, **Media** — passes independently. Core derives the **non-waivable** required Media checks from the approved pinned profile; caller-supplied checks are only additive. A profile with missing, unsupported or invalid structure probes is UNSUPPORTED/FAILED even when its client-chosen signature happens to match. This closes the circular-oracle path in which an untrusted source could define one trivial matching signature and then self-certify a different or corrupt track. A missing/empty MediaPolicy returns a typed negative `MEDIA_POLICY_REQUIRED` / `MEDIA_INVALID` (PR #118 is proposed precursor), not vacuous PASS. Existing static byte-signature validation by itself is **not sufficient** for all real media containers/tracks; before claiming support for a container, a bounded structural probe must validate its promised properties. Initial supported format subset must be named and proven by fixtures (e.g. self-contained MP4 with required A/V track presence, or standalone audio). Ambiguous mux/codec topology, separated A/V, DRM and unknown tracks are UNSUPPORTED; do not invent success, auto-mux or download wrong files. Structural Media rejection may accompany otherwise valid digest; it still blocks acceptance. Source-selected URL provenance alone yields PROBATIVE, not a fabricated PUBLISHED_SHA256/DECISIVE oracle.

Core stores staged bytes and actual artifact digest, issues one terminal from durable evidence and retains restart/idempotency/late-cancel precedence. Crash before witness/terminal must re-derive truth from durable outcome and owned evidence, not repeat external I/O or replenish budgets. Attempts with auth-required/browser-bound signed resource are **not** in this public-file lane.

## 4. Browser-session media: separated prerequisite, never a shortcut

For an authenticated, session-bound or expiring media locator, **STOP this command before external HTTP** and require a separately reviewed, scoped privileged broker byte-delivery contract with origin, authorization partition, selected member, snapshot, host/redirect graph and expiry. Browser cookies/tokens and reusable signed URLs stay in the broker, never Core/CLI/model/Recipe/logs. Broker returns secret-free bytes/provenance only. Core still owns all Media validation and artifact acceptance. Existing S2 delivered-byte handoff cannot be relabeled S3 unless the S3 structural/selection authority is independently reviewed. Do not claim browser-authenticated S3 is supported because public S3 passes.

## 5. Closed preflight and negative matrix

- **Capability**: CLI/browser surface uses a read-only, same-transport, correlated, fresh-aggregate `READ_PROJECTION` probe (legacy 1.0 query) and requires a valid response from Core schema >=1.2.0, major=1, *exactly* the expected AGGREGATE_NOT_FOUND rejection, as in #103 §2.1. Any 1.0/1.1 Core, existing aggregate PROJECTION, peer denial, fence, mismatch, malformed response or timeout stops before contract, work item and HTTP.
- **Scope/identity**: wrong/unselected variant, missing/changed Core-owned candidate record, wrong snapshot/member/artifact, host expansion, old revision, duplicate pending intent, cross-user peer, stale selected evidence → fail closed; no new scope or second network effect.
- **Media/integrity**: no Core-approved profile, caller-chosen permissive signature attempting to waive mandatory profile checks, missing/invalid MediaPolicy, a bogus signature, required track absent, corrupt container, HTML login disguised as video, independent SHA mismatch, oversized/truncated transfer → failed/unsupported Media/Format/Target as appropriate, no accepted artifact, no falsely COMPLETE terminal.
- **Durability**: kill before/after intent commit, after partial bytes, between scheduler outcome/Media witness and terminal, cancel before/during/after accepted bytes, exact replay and old-Core downgrade → no repeated transfer/budget, no accepted false truth, correct frozen stop/result tuple.
- **Security**: unbound cookie/token, supplied browser headers, undeclared redirect, revoked browser auth, arbitrary model-proposed URL and untrusted extension commands → fail closed, no secret echo or automatic fallback to another lane.
