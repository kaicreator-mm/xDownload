## 2. 独立判断

Bounded Collection 有合理价值假设：当用户确实需要一组资源，集合展开、选择和整理有机会减少逐项操作。但当前 HEAD 尚不能证明净体验收益，也没有完整定义支持这一证明的判定规则。

本稿已明确基础下载优先、LLM 不能扩张 Intent、Runtime 执行约束、预算耗尽停止、完整性不确定时提示，以及 G1–G4 失败不直接否定基础产品。这些是有效保障，不应重复报告为“完全缺失”。本轮攻击的重点是这些保障能否形成可解释、可判定且不相互矛盾的合同。

三个核心风险：

1. 31.6 的完整性条件可被弱证据满足，发现漏项仍可能声称全部完成。
2. “有限范围＋停止条件”没有排除有限的通用 crawler；边界测试又使用非强制性的多数式判断。
3. Target/Membership Validation 缺少足以独立于资源推断的证据，确定性执行并不能证明语义判断正确。

## 3. P0 findings

### F01 · P0 · Completeness 的 OR 判据允许把停止或数量匹配当作集合齐全

**位置：** [§31.6，L887–902](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L887)。关联 §11、§29、§18。

**原文依据：** 全部完成的可解释依据为“期望 count/identity 已知；或 collection traversal 达到明确终止条件”。§11/§29 又允许因预算耗尽停止。文档没有明确区分自然集合终点、用户目标边界与执行预算上限，也没有要求已知期望集合和实际结果相符。

**反例：** 相册声明 18 项，工具获得 18 个可读文件，其中一个是重复图，另一个原图遗漏；或已知 18 项但只有 17 项成功；或实际有 30 项，`max_items=18` 后停止。三者都有“已知 count”或“明确停止条件”，但不能证明原始集合全部获取。

**影响：** False Success Rate 被低估；G0/G1 可能通过；UI/CLI 自动化把漏项结果当最终成功。§29 的未完成提示有保护作用，但不能解决 31.6 对何种停止可证明完整的歧义。

**必须修订：** 明确成功所针对的集合，区分发现候选、确认成员、用户选中项、成功获取项。完整性要求成员对应关系及全部选中项正确获取；只有证明覆盖同一个目标集合的自然终点或用户明确指定的有限选择，才可支持完整声明。预算截断、循环、超时、无法访问页面不能提供全集完成证据。对“全部”“前 N 页”“最多 N 项”分别定义完整性含义。

**关闭证据：** 重复替代漏项、已知数量但获取失败、预算截断和伪分页终点都不会触发全集完成；明确选择的 5 项可以全部成功，同时如实说明更大原集合未确认完整。

### F02 · P0 · Crawler 边界仅靠有限性，且必要条件可能被多数答案绕过

**位置：** [§4，L111–151](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L111)、[§53，L1519–1532](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1519)。关联 §8–11、§22、§45。

**原文依据：** §4 禁止“默认”任意递归与全站探索；§53 判断为“如果主要答案为否”则属于 crawler。§45 明确通用 crawler、全站镜像为非目标，但没有给出对显式请求也成立的准入判据。

**反例：** 用户要求“下载该域名前 1000 页中的全部 PDF”。任务有 Intent、有限目标、页数上限、可理解 scope，也会停止；通过 `follow_declared_link()` 遍历同域链接即可做到。它可能满足大部分问题，却依然是受数量限制的通用站点探索。将输出限定为文件不自动证明导航属于一个明确合集。

**影响：** 产品不断以“有预算”为理由吸收通用 crawling；权限、体验、验证与维护成本扩张。非目标声明无法形成可执行的接受/拒绝合同。

**必须修订：** 下载准入需要用户选择的有限资源/链接集合，或可证明的 gallery/playlist/listing 成员关系；不能仅以“同域＋有限页数＋资源类型”创建任意链接 frontier。目标相关性、范围可理解、硬停止应成为逐项必要条件，不能用多数通过抵消某个失败项。明确哪些请求即使用户显式发起也超出产品范围。

**关闭证据：** “同域前 N 页任意链接递归”被拒绝或要求重新定义集合；“明确列表前 3 页”“用户选中 20 个链接”能被接受。拒绝不是因为数值太大，而是缺少目标成员关系。

### F03 · P0 · Target/Membership Validation 缺少独立判据，语义错误可确定性通过

**位置：** [§17，L544–555](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L544)、[§24，L694–703](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L694)、[§27，L778–795](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L778)、[§31.4–31.5，L879–885](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L879)。关联 §33。

**原文依据：** LLM 可推断集合、区分原图与缩略图，Recipe 可同时描述 membership 和 validation；LLM 不负责 final success，候选通过 deterministic validation 后进入 Knowledge。没有定义语义成功的可接受证据及证据不足时的最终状态。

**反例：** 页面中的原图和缩略图都是有效 JPEG；LLM 错认缩略图为原图，再生成对这一 URL/尺寸的校验规则。运行时完全确定性地获取和校验，仍然保存了错误目标。推荐视频也可能具备与真实合集成员相同的格式、标题模式和时长。

**影响：** 检测与验证形成自证闭环；错误知识被提升，G2–G4 反复重放同一个语义错误。存在 uncertain indicator 的要求并不保证系统能察觉自身错判。

**必须修订：** 按支持的资源类型规定目标与成员证据，如明确资源 ID、合集成员记录、可追溯的原图引用、用户确认的具体候选；不能只用被审核 Recipe 自己推断的断言证明自己正确。证据不足允许返回未验证状态。明确哪些目标保证可自动给出，哪些只能经用户确认或试验人工标注确认。

**关闭证据：** 可读但错误的原图、广告、预览和合集外成员都纳入负例；实验使用独立目标清单或盲标真值，不能把模型/候选规则自评直接作为正确标签。

## 4. P1 findings

### F04 · P1 · Scope、选择与预算混在一起，同一句需求可生成不同结果

**位置：** [§7–11，L201–340](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L201)、[§10，L316](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L316)。

**反例：** 用户要求“前 3 页所有 PDF”，每页 50 项且 `max_items=100`。是下载前 100 项、提示不能完成、还是继续到第 3 页？从第 5 页发起“前 3 页”，是站点 1–3 页还是当前起的 5–7 页？`max_items` 是候选数、去重后数还是选中项数？“当前页面”是否包括子 frame、加载更多内容和链接到的附件详情页？

**缺口：** §9 是字段清单，不是字段语义。§10 允许“可解释默认行为”扩张 scope，§37 却要求显式用户动作；何种默认可以不经确认尚未限定。

**必须补充：** 目标集合、选择策略、探索许可、执行上限各自含义及冲突优先级；页数起点、root page 计数、item 的单位、dedup 规则、frame/滚动/详情页边界；默认推断可以做什么，何时必须再确认。UI 与 CLI 显示/输出同一份可理解合同。用理解测试验证用户知道会得到什么和何时停止。

### F05 · P1 · Preview、执行与恢复之间缺少稳定目标和选择版本

**位置：** [§15，L491–513](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L491)、[§38–39，L1027–1067](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1027)、[§41，L1093–1110](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1093)。

**反例：** Preview 中勾选 18 项；下载时合集增删、分页排序变化，或浏览器切换页面/profile。运行时重新执行“全选当前合集”得到新的 18 项，数量相同但目标变化。重试失败项时再次枚举，还可能下载用户先前排除的资源。

**必须补充：** 选择绑定的 root/collection 身份、候选身份和版本；明确全选是冻结当时结果还是包含后续发现项；集合变化、目标无法重新确认时是否要求用户处理。重试只针对原选择中的失败目标；重新枚举和扩大选择是独立动作。此处要求产品语义，不指定 L2 实现方案。

### F06 · P1 · 停止只约束当前探索，任务生命周期可能反复突破预算

**位置：** [§11，L320–340](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L320)、[§19，L584–596](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L584)、[§29，L824–829](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L824)。

**反例：** 每次恢复/重试/AI repair 都重新获得 3 页预算；浏览器与 CLI 同时导航，各自认为还有剩余额度；分页指向同一页，滚动触发后台请求但页数不增长。最终超出用户理解的整体预算，或一直没有自然终点。

**必须补充：** 预算所属单位、累计与重置条件、任务重启和跨入口的继承规则、循环/重复页/无进展停止，以及停止后哪些已选下载可继续。网络请求、详情页与资源传输计数规则需要能解释 CDN、frame 和后台请求，不要求用户理解内部调度。显式扩容记录为合同变更，不能靠自动重试隐式扩容。

### F07 · P1 · 顶层 COMPLETED 与“集合完整性未知”没有明确组合，CLI 可误报成功

**位置：** [§18，L559–580](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L559)、[§31.6，L898–902](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L898)、[§42–43，L1114–1150](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1114)。

**反例：** 用户请求全部，系统发现并成功下载 18 项但无法确认全集；CLI 返回 `completed` 和 18 项成功，脚本便继续下一阶段。或者预算耗尽先返回，后台继续下载，但用户不知道退出状态代表命令结束还是任务结束。

**必须补充：** 明确任务生命周期、选中项获取结果、目标覆盖程度是不同维度；完整、部分、未知、用户选择的子集如何映射 UI/CLI 和同步返回。机器可读结果必须包含目标语义、已知期望数、发现/选择/成功数、完整性状态与理由、stop reason。定义退出类别与 accepted/final 区别，不要求现在冻结参数名或数值编码。

### F08 · P1 · v0 支持面仍宽，Core 与 Conditional 存在依赖冲突

**位置：** [§44，L1154–1193](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1154)、[§54，L1536–1554](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1536)。

**反例：** DASH VOD 属于 Core，但某 DASH VOD 的音视频分离，需要 Conditional 的 mux；课程、跨源合集出现在示例与能力模型中，又被列为 Conditional。团队容易以核心“支持 DASH/collection”的总称承诺超出实际范围。

**判断：** 文档明确实验核心不自动进入 Release P0，这一点成立。本 finding 不把五种实验能力误读为全部首发必做；问题在于实验广度、基础媒体 P0 与条件能力的组合边界仍未确定。

**必须补充：** 按协议、资源种类、合集结构、认证、跨源和媒体处理依赖给出可验收的支持切片。选择一个可独立验证的 Collection 最小切片，其他实验分开作结论；明确不支持情况如何提示。不支持分离音视频的版本不能无条件宣称完成该类 DASH VOD 目标。

### F09 · P1 · G1 无法归因到 bounded navigation，点击减少可能掩盖净体验退化

**位置：** [§47，L1247–1306](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1247)、[§48 G1，L1320–1324](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1320)、[§50，L1377–1398](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1377)。

**反例：** 单页附件一键全选减少 30 次点击，便被解释为 pagination/navigation 成立；新增 Scope/Preview 每次多花一分钟且用户要纠错，点击数依旧更少。20 项里 10 项是错误成员，“items per action”仍很高。

**必须补充：** 用固定正确目标集合比较净任务耗时、主动操作时间、等待、纠错、失败恢复及整理时间；小集合与简单任务加不退化约束。保留完整外部基线，同时做能力消融：single/手动批量 → 当前页面批量 → 加受限展开 → 加语义筛选/组织。分别结论，不能以一种能力的收益证明全部 crawler-like 能力。

**关闭证据：** 至少有“无需导航也成功”“导航确实必要”“小集合不划算”“误选需纠正”四类任务；确认收益来自所声称能力，且正确性没有退化。

### F10 · P1 · G0–G4 缺少预先判定规则，后验阈值和样本筛选允许双向误判

**位置：** [§47，L1249](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1249)、[§48–49，L1310–1373](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1310)、[§57，L1631–1648](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1631)。

**原文依据：** 四种 corpus 已分开，这是正确方向；但“正式阈值在 Product Experiment 后冻结”，没有区分探索试验与独立确认试验。各 Gate 未定义样本单位、失败分母、对照预算、真值、分层汇总、失败处理和不足证据时的结果。

**反例：** G0 用大量普通成功任务稀释 Collection 错误；G2 只保留 AI 成功的 hard cases；G3 重放同一页面缓存；G4 多用户仍共享相同公开资源与会话。反方向上，一个未纳入支持范围的失败也可能被误用来否定整个 Gate。

**必须补充：** 探索数据可用于估计阈值；阈值、主要指标、非退化条件和任务清单必须在独立确认数据打开前登记。按 Gate 确定分母、独立单位和对照条件；样本不足应返回未证实/需补充，而不是任意映射为 FAIL 或 PASS。G1–G4 失败不得绕道通过 G0 混合汇总否定基础产品。

**关闭证据：** 对同一固定数据，不同评审者能得到相同 Gate 结果；失败、放弃、UNKNOWN 和范围外任务均有预先规定的统计处理。

## 5. P2 findings

### F11 · P2 · 组织体验可能重写用户需要的顺序与重复成员

**位置：** [§7，L232–236](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L232)、[§40，L1071–1089](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1071)、[§52，L1494–1515](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1494)。

**反例：** 同一个 PDF 属于两个章节，内容去重后只保留在一处，另一章看似漏讲义；两项同名但内容不同，安全改名后用户无法对应来源；站点按置顶/更新时间排序，系统错误地当成课程顺序。

**必须补充：** 区分字节去重与集合中的成员位置；保存来源和组织映射，允许保守命名与用户调整。将查找、纠错及重新整理成本计入 G1，不能只测自动生成目录的耗时。

### F12 · P2 · Recipe 晋升只要求单次验证，未定义适用范围和失效后的回退

**位置：** [§24，L688–713](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L688)、[§33，L929–944](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L929)、[G3/G4，L1332–1342](https://github.com/kaicreator-mm/xDownload/blob/7007e0db2933163ddd09531769db6b866cb6b805/docs/product/PRD-v0.2-draft.md#L1332)。

**反例：** 规则在一种页面布局通过，之后匹配到另一布局或语言，却静默收集推荐资源。命中率和调用减少提高，目标正确性下降。

**必须补充：** 候选、已验证本地知识和可共享知识的不同声明；记录经验证的适用范围、证据和失效条件。不要求首发公共 Registry，也不要求在本轮设计其架构；G3/G4 需要验证正确性与范围限制，而非仅验证规则能执行。

## 6. G0–G4 专项攻击矩阵

| Gate | 假阳性：怎样可能错误 PASS | 假阴性：怎样可能错误 FAIL | 必须补充的判定保障 |
|---|---|---|---|
| G0 Product Value | 普通任务数量掩盖合集漏项；按资源数加权让大合集主导结果；只统计成功者的时间 | 单个未支持的合集切片失败导致整体产品被否；把受控拒绝当作下载故障；稀有任务与日常任务权重相同但声称代表自然使用 | single/collection、UI/CLI 和首次/重复使用分层；用户任务作为主要单位；预先规定自然分布权重与正确性底线；报告范围外需求但不冒充承诺能力失败 |
| G1 Collection Increment | 批量队列/整理的收益被归因于导航；少点击但等待、误选和恢复更多；“找到了多少”代替“正确获取多少” | 测试只含 1–2 项的小任务，否定真实大合集场景；将低频复杂合集失败否定全部单页批量价值 | 固定目标集合；能力消融；集合大小、结构和导航需求分层；净成本及基础路径不退化；若仅单页批量成立，精确缩减能力而不是统一结论 |
| G2 AI Increment | AI 比 deterministic 基线获得更多工具、预算或登录上下文；只挑 AI 成功的难例；语义自评算成功 | 基线已能解决但没有给 AI 相同上下文；固定时限低于已登记的现实预算；把预算内明确 UNKNOWN 当错目标 | 先固定 deterministic 失败集与判定，再用相同工具、上下文和预算对照；盲标目标真值；同时计量救援收益、误报成功、耗时及成本 |
| G3 Local Knowledge Compounding | 同页缓存、已下载文件或登录会话复用被当作知识泛化；第二次样本比第一次简单；模型调用下降但正确性下降 | 所有任务都换成知识声明范围外网站；要求本地规则跨用户成功才算本地复用 | 同类但新页面/新会话的适用范围内留出任务；控制缓存与已有输出；比较关闭和启用知识的执行；纳入更新后的失效检测、恢复和验证成本 |
| G4 Shared Knowledge | 不同用户实际共用会话或完全相同公开页面；安全复用只检查功能与不含 Cookie；计数一致掩盖错成员 | 要求支持任意站点/账号差异，超出规则声明；一个个性化不适用任务否定适用范围内共享 | 独立用户和授权上下文、范围内/范围外及负例；规则无私人内容/凭据、动作受原 Intent 限制；同时验证目标正确、完整性声明和有界失败；证据不足不宣称安全 |

各 Gate 需要各自主要判据，不能用一个总体“成功率”替代。首次探索试验可以不预设伪精确百分比；但确认试验必须在看见结果前固定规则。G4 属于可选增强，缺少 G4 证据不应阻止基础下载或已验证本地能力。

## 8. 判定与复审条件

**最终结论：NEEDS_REVISION。**

该结论针对锁定 HEAD 的 PRD 产品合同及实验可判定性，不表示 Bounded Collection 已被证明无价值，也不表示需要停止 xDownload。当前稿已经合理保留基础下载产品，并将 AI、知识和共享拆成可独立失败的增强层；应保留这一点。

复审至少需要：

1. 关闭 F01–F03：完整性证据、crawler 准入边界、目标/成员判据能够处理正例与反例。
2. 解决 F04–F07：Intent/Scope/预算/选择版本/停止/最终状态形成 UI 与 CLI 一致的产品合同。
3. 收紧 F08：明确最小支持切片和条件能力依赖，分开 Release 与实验结论。
4. 补齐 F09–F10：G0–G4 有独立确认方案、真值与失败分母，Collection 净收益可归因。
5. F11–F12 若暂缓，必须限制对应产品保证，不能继续将未验证的组织正确性或知识泛化列为既成能力。

后续应针对修订后的新 SHA 再做产品复审；本轮不作 L2、Product Freeze 或 merge 的放行判断。
