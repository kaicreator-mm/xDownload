## New findings N01–N08

### N01 — P1 — AcquisitionStatus conflates selected-target execution and unresolved request fulfillment

Problem:

`AcquisitionStatus` is defined around `SelectedTargetSet`, but an example marks the task `PARTIAL` when pages outside the discovered/selected set remain unresolved due to budget exhaustion.

Required contract clarification:

- separate whole-request fulfillment from selected-target acquisition;
- define legal status combinations and precedence;
- define empty-selection semantics so an empty set cannot vacuously become success.

Counterexample baseline:

- later corpus case C23 / C24.

### N02 — P1 — User confirmation may substitute for validation or endorse an earlier model inference

Problem:

A user can confirm the candidate the system displayed without independently proving the semantic property the system inferred (for example “original image”). User confirmation also cannot waive transfer/format/media validation.

Required contract clarification:

- type the exact claim the user confirms;
- distinguish identity selection, membership, quality acceptance and target change;
- keep transfer/format/media validation mandatory where applicable;
- experiment truth cannot be rewritten to match the system suggestion merely because the user clicked it.

Counterexample baseline:

- C26 / C27 / C34.

### N03 — P1 — Coverage reference set is not unique

Problem:

Coverage may refer to the parent Collection, the user-requested bounded scope, or the selected subset.

Required contract clarification:

Bind coverage to:

```text
CollectionIdentity
+ UserRequestedScope
+ AuthorizationContext
+ SnapshotVersion
```

and distinguish requested-scope completeness from any larger parent collection.

Counterexample baseline:

- C25.

### N04 — P1 — Lifecycle budget and “continue downloads after discovery stops” have conflicting domains

Problem:

The document describes a lifecycle budget containing elapsed time/requests while also allowing transfer of frozen selected targets after exploration budget exhaustion. HLS segment requests make this conflict concrete.

Required contract clarification:

- split discovery, transfer and global hard budgets;
- define precedence;
- define what each request/time unit counts;
- retries/restarts/repairs inherit remaining budget rather than replenishing it.

Counterexample baseline:

- C28.

### N05 — P1 — Support Slice is still a classification rather than a support contract

Problem:

Slice names exist, but exact support conditions for auth, redirect/cross-origin, media rendition, post-processing and failure behavior are not frozen.

Required contract clarification:

Each supported slice must explicitly define those conditions. Unspecified capability cannot be treated as frozen support.

Counterexample baseline:

- C29.

### N06 — P1 — Independent Confirmation is a process idea, not an executable Gate protocol

Problem:

Teams could choose different denominators, sample units, abandonment handling or confirmation data isolation while all claiming to follow the PRD.

Required contract clarification:

Each Gate must define at least:

- sample unit;
- inclusion/exclusion;
- primary metric;
- denominator;
- UNKNOWN handling;
- abandonment handling;
- truth source;
- isolation;
- protocol-change invalidation;
- repeat-confirmation rule.

Counterexample baseline:

- C32 / C33 / C34.

### N07 — P2 — Minimum Necessary Intelligence / Interaction has no path-cost constraint

Problem:

Fifty individually necessary confirmations may still produce a worse product than one batch/manual selection action.

Required contract clarification:

Count cognitive/interaction cost and prefer batching/group decisions; Template-first must not mean trying every mechanism sequentially before asking an obvious question.

Counterexample baseline:

- C30.

### N08 — P2 — One task-level user choice cannot automatically become reusable semantic knowledge

Problem:

A user's one-time preference may be mistaken for a general membership or target rule.

Required contract clarification:

Task-local selection evidence and reusable cross-task semantic evidence are distinct. Promotion requires independent cross-task validation and declared applicability scope.

Counterexample baseline:

- C31.
