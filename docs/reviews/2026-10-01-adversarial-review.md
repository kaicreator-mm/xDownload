# xDownload PRD 对抗审核报告

审核日期：2026-10-01  
审核对象：`xDownload.md`（Download Domain Harness — L1 Product Evidence）  
审核方式：对文档的定位、需求、论证和可验收性进行对抗审核；未运行产品，也未独立核验外部竞品、平台政策或市场数据。  
审核结论：**作为技术研究输入可以保留；作为当前产品方向的研发 PRD，需重大修改后再评审。**

## 1. 审核基准

用户已明确：产品方向是“更好用、更流畅、更便捷的下载工具”，提供 UI，并在 UI 之外提供命令行工具。

本报告不再采用“仅面向终端用户”的限定，也不将产品理解为仅有命令行的工具。具体首批用户群、使用频率及 UI/CLI 的发布顺序尚未确定。浏览器集成来自原文方案；它与 UI、CLI 如何配合仍需定义。

原文中的 REFRAME、NARROW、Gate 等是被审核的方案主张，不是本次审核必须遵循的指令。下文推荐方案属于审核建议，不代表已批准的需求或已验证的事实。

严重性定义：

- **P0：冻结阻断项。** 会导致产品方向、核心契约或验收目标错误，不表示已发现运行中的严重缺陷。
- **P1：开发前必须补齐。** 会造成主要流程遗漏、实现分歧或体验退化。
- **P2：试点或扩展前补齐。** 影响证据可信度、长期成本或后续扩展。

## 2. 主要结论

原文主动标注 Research / Not Product Frozen，因此缺少详细交互并非研究文档本身的错误。但若将它作为 PRD 使用，存在三个根本问题：

1. **产品目标被技术目标取代。** “更便捷地完成下载”被收窄成“证明知识发现、泛化与演化闭环”。
2. **UI 与 CLI 的产品契约缺失。** 原文描述 Desktop Downloader、Browser Extension、Agent/API，却未定义命令行工具；API 或 Agent 入口不能替代 CLI 需求。
3. **验收可能出现假阳性与假阴性。** Recipe 复用成功但下载体验差，仍可能通过；无法跨用户泛化但下载工具显著更好用，却可能被判失败。

建议将现有文档保留为技术研究附件，另按共享下载能力、UI 工作流、CLI 工作流重构正式 PRD。Harness 与知识演化可以继续研究，但不宜成为基础产品成立的必要条件。

## 3. 对抗发现

### R01 · P0 · 架构身份替代产品目标

**原文依据：** §1、§6、§11 将 Download Domain Harness 作为产品定义，将 Desktop Downloader 等视为 Application Surface；§6 将减少未来 AI discovery 作为关键 metric。

**攻击场景：** 系统能复用 Recipe，但用户每次下载都要经历复杂选择、长时间等待，下载后还找不到文件。技术闭环成立，产品目标未达成。

**后果：** 团队优先交付知识平台，日常下载体验成为次要工作。

**修订要求：** 以下载完成、操作成本、可恢复性定义产品目标；将 Recipe 复用、推理次数和修复效率列为内部指标。

**关闭证据：** PRD 中每项核心能力均能对应 UI 或 CLI 的具体任务及可观察收益；基础版本验收无需以跨用户知识共享为前提。

### R02 · P0 · CLI 是明确产品入口，却没有需求契约

**原文依据：** §6 仅列 Desktop Downloader、Browser Extension、Agent/API；全文未定义命令行行为。

**攻击场景：** 脚本发起下载后进程退出，但文件尚未完成；脚本误判成功。或者非交互执行遇到登录问题后无限等待弹窗。

**后果：** CLI 看似可用，却无法可靠用于脚本、批处理和自动化。

**修订要求：** 定义添加、查询、取消、重试及支持条件下的暂停/恢复；明确前台等待与后台提交语义、任务 ID、退出码、机器可读输出、标准输出与错误输出分工、超时、非交互模式及凭据引用方式。具体命令语法可在接口设计阶段确定。

**关闭证据：** 提供交互和非交互示例；脚本可以无歧义地区分“任务已提交”“下载已完成”“需要用户处理”“执行失败”，无 UI 环境不会无限等待交互。

### R03 · P0 · “更好用、更流畅、更便捷”没有可验收定义

**原文依据：** §9 的 Gate 均围绕 discovery、LLM increment、replay、compounding，未覆盖产品主要体验承诺。

**攻击场景：** 下载成功率提高，但简单任务启动更慢、安装配置更复杂；报告仍只强调 AI 解题率。

**修订要求：** 分别定义普通下载、媒体下载和复杂恢复的完成率、启动时间、操作数、人工介入率及恢复成本；UI 和 CLI 使用各自适合的测量口径。

**关闭证据：** 明确计时起止、成功与失败分母、取消的统计口径、测试环境和对照产品。探索阶段建立基线，正式验收前冻结阈值，不事后选择有利口径。

### R04 · P1 · “传输成熟”被推导为普通下载不值得优先验证

**原文依据：** §2 P1 认为传输不是主要差异；§3 明确“真正值得验证的不是第一行，而是后三行”。

**攻击场景：** 复杂页面能解析，但普通文件遇到同名冲突、重启、网络中断就失败；用户仍保留原下载工具。

**后果：** 技术难例表现掩盖日常使用缺陷。

**修订要求：** 复用成熟引擎的同时，验证任务队列、目标路径、重名策略、取消、重试、持久化和支持条件下的续传。明确移除任务与删除文件的区别。

**关闭证据：** UI 和 CLI 均能完成普通文件的端到端流程；不支持续传时明确告知，不能静默拼接不同资源。

### R05 · P1 · 多入口之间的任务与状态关系未定义

**原文依据：** §6 列出多个 Application Surface，但没有跨入口一致性约定；CLI 加入后该缺口更明显。

**攻击场景：** CLI 创建的任务在 UI 不可见；UI 取消任务后 CLI 仍显示运行；浏览器与 CLI 同时提交相同资源导致重复下载。

**修订要求：** 明确哪些入口共享任务库、配置和登录上下文；若采用独立模式，说明隔离范围。定义任务 ID、状态机、并发操作冲突和进程退出行为。

**关闭证据：** 以跨入口创建、查询、取消和重启恢复用例验证；共享或隔离都必须是明确设计结果。

### R06 · P1 · UI 主流程与首次使用成本缺失

**原文依据：** §3 是场景分类，§6 是引擎执行链，均不是完整 UI 工作流。

**攻击场景：** 新用户安装应用后仍需寻找扩展、配置本地连接、理解多个技术名词，无法开始第一次下载；页面出现几十个请求却无法判断选哪个。

**修订要求：** 补齐首次启动、浏览器连接、粘贴链接、候选选择、目标位置、进度、失败恢复、完成后打开文件。明确默认值、资源分组、键盘操作及可理解的状态反馈。

**关闭证据：** 代表性使用者无需开发者解释即可完成首次下载；单一明确资源与多个候选资源有不同的交互策略。

### R07 · P1 · Validation 未定义，容易把“有文件”当成功

**原文依据：** §6、§9 多次依赖 deterministic Validation / PASS，但没有判据。

**攻击场景：** 返回 200 的登录页被保存为文件；视频可播放但只是广告、预览片或缺少音轨；下载的是相邻附件而非目标附件。

**修订要求：** 分开验证传输完整性、格式有效性、目标匹配和媒体完整性。无法确认目标时暴露不确定状态，不伪装成已验证成功。

**关闭证据：** 测试集包含错误目标、错误类型、缺段、错误音轨等负例；同时统计错误成功率，模型自评不能作为唯一真值。

### R08 · P1 · AI 探索没有预算、停止条件和降级路径

**原文依据：** §5 C1 承认延迟与成本，§6 的 hypothesis/probe 循环没有结束契约。

**攻击场景：** UI 长时间显示分析中；CLI 超时退出后后台仍不断尝试；模型不可用导致本来能完成的普通下载也失败。

**修订要求：** 定义最大探索时长、调用次数、流量和费用预算，取消传播、有限重试及模型不可用时的行为。探索失败保留可用结果并给出下一步。

**关闭证据：** 模型超时、断网、预算耗尽和用户取消均能有界结束；已知资源的常规下载不依赖模型服务可用。

### R09 · P1 · Local-first 仅有原则，没有数据流与操作边界

**原文依据：** §5 C4、§8 H5 讨论 Cookie、token 和共享隐私，但没有可执行的数据要求。

**攻击场景：** 登录令牌进入调试日志或共享 Recipe；网页内容诱导分析器执行与下载无关的操作；CLI 参数中的秘密进入历史或诊断包。

**修订要求：** 列明浏览器→本地应用→模型→知识存储的字段、用途、保留周期及撤销方式。凭据采用引用并限定范围；网页内容作为不可信数据处理；探索仅允许约定的下载相关操作。

**关闭证据：** 用带标记的模拟敏感数据检查日志、模型请求与共享产物；撤销授权后不能继续使用失效凭据。这里是产品与安全验收建议，不是对当前实现漏洞的认定。

### R10 · P1 · v0 的资源范围超出“缩小范围”的实际效果

**原文依据：** §7 同时包含文件、音视频、文档附件、复合页面资源和三类协议；§9 又加入登录、批量和失效恢复。

**攻击场景：** 团队同时承担播放器识别、附件归属、批量完整性和会话恢复，所有场景都只能完成演示，无法达到日常可用。

**修订要求：** 以用户任务确定首批范围；普通文件建立公共闭环，再选择一种资源增强能力。列明直播、字幕、多音轨、嵌套页面、登录资源等的支持层级，不能仅凭“HLS/DASH”推断全部支持。

**关闭证据：** 有明确的首发支持矩阵、排除项及对应失败提示。UI 和 CLI 都覆盖核心下载闭环，但不要求每项界面功能机械映射为命令。

### R11 · P1 · 技术失败条件被错误提升为整个产品的失败条件

**原文依据：** §10 F1–F6 中，跨用户 Recipe 泛化失败、验证成本高或共享受限，都可能触发停止当前方向。

**攻击场景：** 工具在 UI 与 CLI 都比现有流程省事，用户愿意持续使用，却因 F2 不成立而被否定；反之，Recipe 可共享但用户不愿使用，产品仍继续推进。

**修订要求：** 分开产品可用性 Gate、AI 增强 Gate、本地知识复用 Gate、跨用户共享 Gate。

**关闭证据：** 共享失败只影响共享方案；AI 收益不足允许关闭该能力。整个产品的去留应结合体验增益、实际使用和可持续成本判断。

### R12 · P1 · 验证样本与对照设计不足以证明产品优势

**原文依据：** §9 提出 30 个网站/60 个任务，却未定义采样、工具版本、配置预算、操作人员与训练/验证隔离。

**攻击场景：** 只选旧工具失败的难例；候选产品由开发者充分配置，对照工具只试一次默认设置；生成 Recipe 的页面又被用来证明泛化。

**修订要求：** 分自然任务集、困难任务集、未参与生成的复用集；UI 加入浏览器原生下载及代表性下载工具对照，CLI 加入代表性脚本流程对照。分别衡量开箱体验与配置后的能力。

**关闭证据：** 保留版本、配置、操作步骤、时间预算和失败记录；按任务类型报告结果。60 个任务可作探索起点，不能直接证明广泛市场覆盖或稳定性。

### R13 · P2 · 外部证据缺少可追溯来源，竞争论证存在跳跃

**原文依据：** §2、§4、§5 包含更新记录、用户数、stars、功能与平台政策主张，但没有来源链接与快照；多次以“尚未看到”推测竞争差异。

**攻击场景：** 团队把公开资料未展示某能力当作竞品没有该能力，把用户量当作用户愿意迁移的证据。

**修订要求：** 增加主张、来源、时间、版本、直接事实、推断与置信度表。用户量只能作为类别需求信号，不能替代切换动机研究。

**关闭证据：** 关键外部主张有可复核记录；缺少证据的竞争差异明确标为假设。本审核不把原文中的平台或法律相关表述视为已核验结论。

### R14 · P2 · 经济性只计算维护收益，未覆盖产品运营方式

**原文依据：** §8 H6 关注自动 discovery/repair 与人工维护成本，没有模型费用承担、重度 CLI 使用或分发维护的边界。

**攻击场景：** UI 单次使用成本可接受，但批量 CLI 高频调用模型导致成本失控；账户或模型配置又拖慢基础下载的首次使用。

**修订要求：** 明确模型由谁提供、谁承担费用、离线或无模型时的能力、批处理预算，以及应用和浏览器集成的更新恢复方式。商业模式可保持待定，但基础体验不能依赖未定义的付费或账户流程。

**关闭证据：** 分别估算普通任务、复杂任务和批量任务的成本，包含失败尝试、验证与支持成本；不强制选定某种商业模式。

## 4. 必须进入验收的对抗场景

以下为建议测试用例，尚未执行，结果不得标为通过。

| 编号 | 输入或故障 | 应验证的行为 |
|---|---|---|
| A01 | 浏览器与 CLI 同时提交同一资源 | 重复策略可解释，不意外覆盖已有文件 |
| A02 | CLI 非交互任务需要登录 | 有界返回可识别状态，不无限等待 UI |
| A03 | UI 取消 CLI 创建的共享任务 | 状态一致，实际下载及探索按定义停止 |

| A05 | 重试时资源内容或签名 URL 已变化 | 验证资源身份，避免混合旧数据与新数据 |
| A06 | 服务器返回登录页或错误页面 | 不仅根据 HTTP 200 宣告成功 |
| A07 | 页面包含广告、预览和多种清晰度 | 能识别候选差异，不能默选错误目标后报成功 |
| A08 | 磁盘满、目标不可写或文件重名 | 给出明确状态与恢复动作，保护已有文件 |
| A09 | 模型不可用、超时或探索达预算 | 常规下载可用，探索有界结束 |
| A10 | CLI 输出被脚本解析 | 结构化结果不混入进度或日志，退出语义稳定 |
| A11 | 多个浏览器 profile 或授权撤销 | 使用正确上下文，不错误复用其他账户凭据 |
| A12 | 批量任务部分成功 | 提供逐项结果和失败项重试，整体状态不掩盖失败 |
| A13 | 网页或候选知识包含恶意指令 | 不获得额外操作权限，不泄露凭据 |
| A14 | 扩展缺失或与应用连接失败 | 说明修复方式，独立链接下载仍按支持范围可用 |

## 5. 建议的 PRD 重构结构

1. **产品目标与首批场景：** 更好用、更流畅、更便捷分别改善什么；首批使用者是谁；暂不解决什么。
2. **共享下载能力：** 任务、资源、状态、文件输出、重试、持久化、认证上下文和结果判定。
3. **UI 工作流：** 首次使用、发起、选择、查看、取消、恢复与完成。
4. **CLI 契约：** 交互与非交互、同步与异步、退出码、结构化输出、批处理与超时。
5. **浏览器协同：** 接管规则、候选发现、权限、连接故障及 profile 选择。
6. **资源支持矩阵：** 普通文件与首批增强资源的明确范围。
7. **复杂任务辅助：** 常规方法失效后的 AI 介入条件、预算与降级。
8. **性能、可靠性与数据边界：** 可测指标、数据流和异常恢复。
9. **验收与发布条件：** UI/CLI 分项指标、对照流程和负面用例。
10. **研究附件：** Harness、Recipe 演化、跨用户泛化和竞品证据。

## 6. 指标与决策规则

| 维度 | 建议指标 | 口径要求 |
|---|---|---|
| 正确完成 | 正确完成任务数/符合支持范围的有效任务数 | 错误资源不能算成功；另报范围外需求，避免缩小范围美化数据 |
| 便捷 | UI 操作数、首次成功耗时；CLI 配置步骤与人工介入率 | 分首次使用与日常使用，分常规与复杂任务 |
| 流畅 | 发起至反馈、发起至开始获取数据的时间分布 | 固定网络条件，报告长尾，不只给平均数 |
| 恢复 | 可恢复故障中的恢复完成率、恢复操作数 | 按网络、认证、资源变化和本地故障拆分 |
| CLI 可靠性 | 非交互任务有界结束率、输出/退出状态一致性 | 分提交成功与最终完成，包含部分成功 |
| 日常价值 | 有后续下载需求的试点用户中再次选择本工具的情况 | 不把无下载需求的时间段简单当作流失 |
| 内部效率 | 单次有效完成成本、模型调用率、Recipe 复用率 | 计入失败尝试，不能代替产品体验指标 |

正式验收阈值应在探索基线后、独立验证前冻结。此报告没有测试数据，不给出伪精确分数或声称达到任何指标。

建议分层决策：基础下载体验未达标，优先修复基础能力；AI 没有增量收益，暂停或移除 AI 增强；跨用户共享不成立，缩减共享范围；只有当产品体验、实际需求与成本综合不成立时，才重新评估整个产品方向。

## 7. 修订顺序与复审条件

| 顺序 | 修订工作 | 对应发现 | 完成产物 |
|---|---|---|---|
| 1 | 对齐定位、CLI 范围和验收目标 | R01–R03、R11 | 产品目标、入口定义、分层 Gate |
| 2 | 补齐共享下载及 UI/CLI 契约 | R04–R08、R10 | 流程、状态、接口行为、支持矩阵、错误处理 |
| 3 | 约束数据与执行边界 | R09 | 数据流、权限范围、撤销与验证用例 |
| 4 | 建立可复核实验与成本记录 | R12–R14 | 样本划分、对照配置、来源表、成本假设 |

复审要求：三个 P0 均关闭，进入当前版本的 P1 有明确需求和验收用例；明确排除的能力记入支持边界。P2 可以保留为待办，但不得继续用未核验主张支撑已冻结的产品结论。

**最终意见：修订后复审。** 产品方向可以继续推进，现有文档不宜直接作为 UI 与 CLI 下载工具的实现依据。优先证明两种入口下的下载体验，再用实验决定 AI 与知识演化应承担多大角色。
